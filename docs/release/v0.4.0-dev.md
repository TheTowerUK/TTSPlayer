Increment the dev patch (`0.4.0-dev.2+1`, …) for checkpoint commits during the cycle. Bump to `0.4.0+1` only when M3.5 ships.

---

## Why v0.4.0 maps to M3.5

M3 delivered the Windows-first personal media shell. M3.5 is the **bridge milestone**: the same Flutter app gains HTTPS catalogue and media streaming so phones on the home network can browse and play without SMB mounts.

This is a platform-access expansion, not a content-type expansion. **M4 (Rich Media Libraries)** remains documented but **out of scope** until M3.5 closes.

---

## M3.5 objectives (this cycle)

| Area | Deliverable |
|---|---|
| NAS serving | Caddy or Nginx on TNAS serving `catalog.json` and media with range requests |
| Path resolver | Map scanner `file_path` values to HTTPS stream URLs |
| Client HTTP mode | Load catalogue from URL; stream playback over HTTPS |
| Mobile settings | NAS base URL and catalogue endpoint configuration |
| Mobile builds | Android / iOS smoke builds on home Wi‑Fi |
| Graceful degradation | Last-good catalogue retained on network failure |
| Desktop unchanged | Windows local/UNC + local scanner continue to work |

→ Full criteria: [network-client-foundation.md](../roadmap/network-client-foundation.md)

## Explicitly out of scope (v0.4.0-dev)

- M4 image library viewer and grid UX
- M5 music / M6 books
- App Store / Play Store release polish
- Remote control, cast, multi-device sync (M7)
- Running `indexer.py` on mobile devices
- TMDB or external metadata
